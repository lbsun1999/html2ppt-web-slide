从原始需求到可持续迭代的汇报#

本skill有两类职责：把用户材料归纳成有证据、有层级的内容；调用平台已经实现的编辑、放映、保存和导出功能。文案与布局可以按任务变化，功能不能每次重新实现或随内容改写丢失。

首次接触本项目时#

本流程不依赖作者历史会话或其他已安装的学校skill。取得完整项目目录后，从SKILL.md定位资源，读README中的环境与入口说明，再读结构化接口和本次页型对应的版式细则。两校正式HTML、五类成熟页数据、局部CSS及素材都在包内；不去上一级目录寻找“原版”。

先判定需要哪种能力：直接打开学校HTML即可阅读、编辑、管理大纲、新建和保存文稿、放映，并可离线导入XLSX／CSV；AI通过脚本构建独立HTML需要安装包内package-lock.json锁定的依赖，PDF/PPTX导出还需启动本地服务。命令从项目根目录执行，路径以实际解压位置为准，不写作者电脑的绝对路径。依赖恢复、启动步骤与浏览器要求以README为准；不把Python或旧模板的TeX工具链加为普通使用要求。

新建汇报可以这样向AI提出任务：

请使用本项目SKILL.md和北科母版，把这些论文、实验记录和图表整理成一次15分钟研究进展汇报。听众是课题组。先讲问题与现状，再讲方法、实验、局限和计划；缺失数据明确占位。保留编辑、备注、放映和导出功能，交付独立HTML及PDF/PPTX。按材料决定页数，按包内规范检查每页密度、短尾行、公式、表格和图注。

继续成稿可以这样说明：

请以我最新保存的HTML为起点，只修改方法与实验部分。我手动调整过文字颜色、列表、图像取景和备注，请保留。新增实验条件说明，修正对应来源，重新检查目录范围与版式。不要重新生成示例覆盖成稿。

这些是调用示例，不限制研究主题、时长或输出格式。未指定学校时结合用户材料选择；缺少会改变身份或内容的关键信息再询问。

1. 先判定本次任务#

任务起点应保留的内容
新建真实汇报用户材料＋最接近的学校母版平台功能、学校标识、版式规则；替换示例文案
修改已有汇报用户最新保存的HTML中的project-data未要求修改的事实、页面ID、人工格式、素材、备注、来源与交互
调整母版项目源组件与两校示例已确认的reference快照；两校共同修正
增加平台能力src、渲染与导出链路已有交互契约与旧文稿兼容性；用回归验证

不能用重新生成全部示例代替修改用户成稿。不能因为用户要换文案，就覆盖其已选的列表、局部颜色、页尾结论、媒体取景或备注。

2. 将需求变为可追踪的内容#

先阅读用户原话、论文、图表、实验记录和已有HTML，形成工作清单：汇报受众、目的、时长或页数范围、必须保留的内容、当前成果、待讨论问题及来源。能从上下文推定的常规选择直接处理；只有缺失信息会改变结论或任务范围时才提问。

对材料分清四种状态：已有证据的事实、初步观察、待验证假设、后续计划。数据、作者履历、实验结论、文献和DOI都不能凭空补齐。缺失内容写明确占位或保留问题，不把教学数字当作真实结果。

归纳文案时保留对象、条件、比较口径与限制。删除重复背景和空泛形容，把长段整理成“主题—判断—证据—解释”。每个板块通常不超过四点；标题应概括实质内容，不只写“研究内容”“主要工作”等泛名。

3. 提纲与逐页结构#

先协商结构，再加工现有页面#

首次制作整篇文稿时，AI先给出章序和逐页标题，人工确定重点与叙事是否准确，再开始逐页制作。若用户已经提供定稿大纲，或明确授权直接完成，不重复等待确认；现有文稿的局部修订也无需重新走整篇确认。结构确认不代表数据、结论和引用已经审核。

双方可以用同一份MD／TXT作为沟通结果，#只表示整篇标题，##表示章节，###表示单页标题。例如：

# 面向动态环境的调度方法研究
## 问题背景与意义
### 研究问题与应用场景
### 相关方法与关键不足
## 方法与实验
### 方法框架与目标函数
### 实验设置与对照结果
## 总结与计划
### 已完成工作与后续验证
## 补充材料
### 参考文献
### 作者简介

最后的“补充材料”可在弹窗勾选为附录，无需把章名强行改成“附录”。章、页按出现顺序排列，标题中的手动分行写成<br>或字面量\n。普通说明不创建新页，放入对应页面备注；材料仍需AI整理为正式正文。可直接导入大纲示例。

建议的首次协作指令：

请先阅读这些材料，给出“总标题—章节—逐页题目”的大纲，以及各页主证据和缺失材料。我们确认结构后，以当前学校HTML为底稿复用相应页面，补写有来源的文案。保留人工格式、位置、媒体与备注，缺失事实保留明确占位，不重做平台功能。

制作过程中管理大纲#

  1. 点击顶部“新建HTML”旁的“文档大纲”。弹窗初始内容来自当前页面，包含现有章节与每页题目；可现写、粘贴或读取MD／TXT文件。支持UTF-8及带BOM的UTF-16，无法识别编码时提示另存为UTF-8或直接粘贴。
  2. 默认“更新当前文稿”：改题和重排通过下方对应页映射应用到原页，保留ID、正文、图表、字符／段落格式、位置、引用与备注。重排优先按唯一同名题目对应，改名保留原位置的对应关系；重复标题、跨章移动或整段替换后要检查下拉框，不能仅依赖自动猜测。
  3. 新增题目可以选择“新建内容占位页”或复制已有页。删去题目意味着对应页面移出本次文稿，预览会统计数量；决定保留的页面应仍出现在大纲中。目录、过渡页和结束页可配置，已有混合过渡结构默认保留；改变过渡页开关后统一调整。
  4. 勾选“最后一章为附录”，末章使用“附录”章节标签、默认不生成过渡页、不进入正文目录。勾选状态从现有章属性或名称初始化，改名后也可以明确保留附录身份；取消勾选则末章按普通章节处理。目录本身的“包含附录”选项仍可独立开启。
  5. 选择“另建文稿”时沿用当前学校主题，所选旧页是副本并使用新ID，未匹配页为待加工占位；新文稿需要另选保存文件。点击“填入格式示例”也只修改弹窗并切到此模式，确认前不动原稿。
  6. 核对页数、章节和对应页后应用；层级有误会显示具体问题。取消不改稿，应用可撤销；必须保存HTML才落盘。更新当前文稿保留原文件关联及文件名，封面总标题与文件名不强制相同。

标题改变只更新结构，不自动重写研究事实。AI下一步应复用最接近的formula、summary、profile等页，核对旧内容与新题目并替换相关正文、图表及来源。不能拿一页旧实验表改题后就称作新研究成果。新增草稿有outlineDraft标记，经过内容加工和检查后再清除；该标记不等于额外的强制审批流程。

谁来决定，谁来落实#

人工决定汇报目的、材料可公开范围、研究事实、重点取舍和最终采用的结论；AI负责从材料归纳结构和文案、追踪来源、选用成熟版式、保留人工修改，并修复布局和导出问题。信息足够时AI应继续完成，缺少会改变结论的事实再提问。人工可以直接精修，AI继续时必须读取最新保存的HTML，而非最早导入的大纲或中间JSON。最终人工审核专业内容及PPTX，不代替AI的逐页自查。

常见研究叙事为：研究问题与背景 → 现状及缺口 → 方法与假设 → 实验设计和证据 → 结论与局限 → 计划。按用户材料调整，不强制保留示例中的“制作起步／模块与内容”等教学章节。

封面、目录、章节过渡、正文、附录、结束页各司其职。章节从01连续编号，完成一章全部内容再进入下一章；目录从实际章节同步编号与页码范围。参考文献、资料来源、作者和补充材料归附录，默认不列入正文目录。真实文稿不必凑20或30页，示例页数的4／5倍数只用于方便预览。

逐页确定以下信息后再排版：

字段内容标准
title本页对象、问题或有依据的判断
lead可选，补充背景／阅读线索，不重复标题
主证据图、表、公式、算法、时间线或明确的事实关系
解释说明如何读证据、关键条件、适用范围或局限
summary可选，一句有内容的结论；深色页尾条
source/sourceUrl对应本页事实的来源，可定位、可点击
notes讲解推理、过渡和补充，不占画布

例如材料只有“方法A在场景一耗时较低”，不能直接写“方法A全面优于其他方法”。应把场景、计时范围、重复次数和其他指标补全后再形成结论；这些信息缺失时保留“场景一的初步观察”及待核对项。页尾结论可以据已知材料凝练并平衡留白，但不能添加不存在的优势。

排版前先根据真实信息量选择布局。优先复用成熟的history、formula、summary、references、profile页；普通内容使用文本、媒体、表格等模块。不要先放满高卡片再往里填两行字，也不要删掉成熟表格、公式或履历的结构后只保留近似外观。

4. 结构化数据是交接中心#

用户原始材料 → 内容提纲 → project-data → HTML渲染 → 人工精修 → 保存HTML → 下一轮AI读取同一数据。

项目以{version,title,theme,grid,slides}组织。页面用稳定id、kind、章节与来源字段；普通内容在modules中，成熟特殊页使用referenceLayout和legacy_*字段。字符级格式在rich，逐段列表、对齐与段后距在paragraphs，正文平移在textPositions，公式保留LaTeX，媒体保留比例、取景及原始资源。可选outline只记录最近应用的结构大纲，之后反向生成当前大纲以实际slides为准。

修改已有HTML时，用DOM解析script#project-data[type="application/json"]，验证后复制数据，再做本次必要修改。不要从截图OCR重建已有源数据，不丢弃不认识的可选字段，不重新生成仍在使用的页面／模块ID。删页与重排后重新同步章节、目录和引用目标。

使用当前平台的build-document.mjs生成HTML，复用同一份运行时和CSS。它负责嵌入代码、字体和资源，不要求AI手工维护第二套工具栏。运行示例：

node scripts/build-document.mjs ect/本次文稿.json 正式汇报.html --export

正式源稿放用户指定目录，PDF/PPTX放output。中间JSON、检查截图放ect。安装目录是母版资源，不是用户汇报的默认输出位置；普通制作任务不改母版。

读取HTML数据的最小做法#

浏览器中可用document.querySelector('script#project-data').textContent读取JSON。文件端处理本平台生成的HTML时，也可按脚本节点提取；不要全局替换HTML中的同名文字，因为内嵌源码、数据和预览可能同时含有它。以下Node.js示意从项目根运行，sourcePath换成用户最新文件：

import fs from 'node:fs/promises';
import {validateProject} from './src/model.js';

const sourcePath = '用户最新保存的汇报.html';
const html = await fs.readFile(sourcePath, 'utf8');
const match = html.match(/<script\b(?=[^>]*\bid=["']project-data["'])[^>]*>([\s\S]*?)<\/script>/i);
if (!match) throw new Error('未找到Web Slide的project-data，请核对源文件。');
const project = structuredClone(JSON.parse(match[1]));
validateProject(project);
// 定位目标页面／模块，修改本次范围，保留其余字段及ID。

当前构建器接收结构化模型并生成自包含HTML。特殊页的legacy_*与可选字段应完整保留；需要改变文本的字段若已有rich和paragraphs，同步更新对应格式，使运行段拼接与新文本一致，不能保留失配的旧运行段或顺手清空全篇格式。

新建汇报从选定学校母版复制theme和所需结构，或调用构造器后明确装入学校主题与内嵌标识。不要只用通用newDocument缺省主题就声称已套用学校正式示例。复用成熟页前检查其包内快照和字段映射；applyReferenceLayout会写入默认字段并清空modules，仅对新页或明确重建的页面调用。

5. 人工修改如何保留#

下一轮优先读取用户最新保存的HTML，不读取旧中间JSON替代它。先识别用户的新增、删减和格式调整，再处理新需求。局部修改只动相关页面与字段；未修改部分保持事实、ID和设置稳定。

人工端保存优先覆盖已关联文件；另存为选择新文件后关联新目标。使用打开HTML建立句柄，双击或拖入时首次保存需指定原文件。浏览器不支持直接写回时会下载副本，AI应确认实际拿到哪份文件，不能把旧原稿当最新版本。取消、拒绝写入或写入失败时不应切换关联或丢失内存修改。

特别保留：局部粗细／颜色／字号、逐段列表／对齐／段后距、正文平移、图注开关、媒体裁剪及自定义比例、目录增删／自定义项、无过渡页附录、来源链接、LaTeX修改、逐页备注、封面信息标签及可编辑页尾句。不能把它们恢复为示例默认值。

独立文本块的textBox／boxTone、表格rowHeightPt／cellPaddingPt及成熟页对应设置也属于人工改动。选区格式控件读取当前样式，不把工具栏历史值反写为新格式。留白建议允许按实际空间收紧，不能为了通过旧24px间距规则删掉可完整显示的内容。

内容修改导致容纳不下时，先改文案和结构，再调整区域或拆页。不能为保留旧外框而缩小正文、遮挡下一块或取消检查；人工指定的字号和重要材料需优先保留。

6. 功能如何持续迭代#

新增能力在平台源组件实现，复用渲染、编辑与导出链路，并通过现有构建器带到学校示例和新文稿。学校换色或换素材只改变主题和内容，不复制出功能不同步的编辑器分支。

功能契约升级后仍须成立
文字编辑点击控件保留选区；字符格式局部修改；段落可混排；保存重开有效
模块编辑网格调整、移动、长按与撤销有效；越界／真实溢出仍提示
目录与章节自动同步序号／范围；保留用户增删；附录默认排除
公式单份显示、可复制修改LaTeX；语法及布局错误不覆盖原式
媒体自定义比例、等比取景、实际等高、图注可删除
浏览与放映单页／单列／多列；双击总览；滚轮缩放、拖动、两次Esc
备注每页独立保存，演讲者可显示／隐藏，观众视角不暴露备注
文件与导出HTML自包含；保存写回关联文件、另存为独立选择、错误不丢数据；PDF真实16:9；PPTX原生文本保留格式、显式换行和备注

数据结构变化时提供兼容缺省或显式迁移，不能无声丢弃旧格式。version是数据协议版本，不把每次改文案都当作协议升级。只有确需不兼容迁移时才调整版本，并保留可验证的迁移入口。

保留测试和源代码用于维护；不是把测试产物作为正式材料交付。新增功能要覆盖正常操作、错误输入和HTML往返，并检查相关PDF/PPTX；只改内容也要做逐页视觉检查。

换校时复用公共组件，不复制另一套运行时。依次更新主题变量、校徽／校名标识、校园占位图、学校介绍／历史、页脚和素材来源；随后全篇查残留校名、色名及历史年份。派生浅底和正文墨色不冒称官方标准色，不能把别校的校训、建设身份或学校成果保留下来。

7. 完成标准#

先按版式细则与错误复盘检查内容密度、标题层级、短尾行、表头、公式和对齐，再逐页执行版面检查。尤其检查“无溢出但半页空白”“外框对齐但内容悬空”“通用CSS污染原页”等脚本不一定能发现的问题。

实际编辑选中文字、公式、表注或页尾句，保存HTML并离线重开。检查来源跳转、章节范围和备注，再导出PDF/PPTX验证物理页面和文本效果。给用户交付正式文件及必要使用说明，指出真实限制；不把仍有明显问题的示例称为已完善。
