# 项目结构与依赖

## 运行依赖及用途

文档大纲由`src/outline.js`解析、映射和更新数据，`src/outline-import.js`提供制作中可反复打开的管理弹窗。`src/table-text.js`负责当前表格的制表符文本往返与批量修改，`src/table-text-editor.js`显示金色Tab间隔并同步滚动；段落对齐继续复用`src/rich-text.js`，不增加编辑器分支或运行依赖。配套大纲示例位于`docs/大纲示例.md`。

v0.1.2未增加运行依赖。`editable-layouts.js`负责作者／计划预设，`profile-card.js`保留固定身份卡，`table-blocks.js`负责履历及分组表格，`text-block-selection.js`管理临时多选；专用样式集中在`structured-layouts.css`并由共享CSS加载器统一内嵌。删除已不使用的旧预设辅助函数，测试及中间文件仍放ect，不进入分享包。

| 依赖 | 实际用途 | 入口 |
| --- | --- | --- |
| esbuild | 工作台启动时打包浏览器脚本；生成独立 HTML | server.mjs、scripts/build-document.mjs |
| exceljs | 读取 Excel 工作簿与合并单元格 | server.mjs |
| katex | LaTeX 语法校验、预览和公式渲染 | src/formula.js |
| playwright | PDF 导出及 PPTX 对象测量、媒体截图 | server.mjs |
| pptxgenjs | 写入可编辑 PPTX | server.mjs |
| jszip | 规范PPTX段落XML，补全中文断行规则并保留原生列表属性 | src/server/pptx-typography.mjs |

v0.1.3将此前已被依赖树使用的JSZip显式列为直接依赖，用于PPTX段落规范化。以上六项均由实际功能引用，不删除或误移到仅开发依赖。`node_modules` 是安装产物，不手动裁剪其内部文件；分享源码时可不打包，由 `npm ci` 恢复。独立 HTML 的浏览、编辑与放映不读取 node_modules。

## 目录用途

| 位置 | 用途 |
| --- | --- |
| 根目录两份北科 HTML | 正式、可直接打开的源稿 |
| src/ | 编辑器、渲染、模型与学校变体 |
| src/server/ | 服务端必需的学校资源和共享样式加载 |
| assets/ | 两校实际使用的标识、照片与来源记录 |
| scripts/ | 生成、检查、预览及清理等维护命令 |
| reference/ | 三份参考HTML及截图／哈希；navigation第10页提供通用时间轴 |
| docs/ | 说明、原始样式规范和正式预览图 |
| tests/ | 回归测试；fixtures/ 为固定测试视频，不参与默认示例 |
| output/ | 正式 PDF/PPTX |
| ect/、test-results/ | 可再生检查产物，清理后按需重建 |

根目录保留可直接打开的正式HTML、使用说明、技能入口及运行入口；src存放模型与编辑逻辑，assets存放学校素材，docs与reference分别承担说明和已确认参考，output只保留北科科研／红色政务正式PDF/PPTX。不移动已认可源稿和组件样式来制造目录变化。

GitHub与版本包包含源码、独立HTML、学校素材、说明插图、reference和四份正式PDF/PPTX；不包含node_modules、ect、test-results、本地备份和日志。依赖用package-lock.json锁定并通过npm ci恢复。发布前检查所有README本地链接可到达，避免忽略output后留下失效的PDF/PPTX链接。

## 维护命令

```powershell
npm.cmd start
npm.cmd test
npm.cmd run test:e2e
npm.cmd run build:examples
npm.cmd run clean
```

`build:examples` 更新北科科研与红色政务 HTML；追加 `-- --export` 可导出正式 PDF/PPTX，需要本地服务运行。`clean` 仅清理 ect 和 test-results，不处理正式文稿、output、reference、学校资源或依赖目录。正式材料不要放在临时目录。

运行编辑器只需 Node.js 20.10+、Chrome/Edge 和上述 npm 依赖。Python/Pillow 仅供部分检查、拼图工具使用；普通用户不必安装。

## 当前学校交付结构

主分支只展示北科科研和北科红色政务两套HTML及四份PDF/PPTX。丽水学院不维护接口分叉的长期分支，使用同一源码生成最新版Release的额外ZIP；转换配置、必要学校素材继续在主分支维护。

- npm.cmd run build:lishui：在ect/lishui-release生成单份丽水HTML。
- 追加 -- --export：在该临时包的output生成PDF/PPTX。
- node scripts/package-lishui.mjs：将已提交的共用源码与新生成丽水文稿打成额外资源包，不装入北科成稿。

启动入口拆为保持真实CRLF的ASCII启动.cmd和可记录错误的scripts/start.mjs；Windows不会再依赖含中文的批处理逻辑。SVG、主题色、离线传送与保存路径选择均复用共用接口，未新增运行依赖。
